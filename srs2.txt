2GitLens Visual – Software Requirements Specification (SRS) V2

Project Name: GitLens Visual
Version: 2.0
Date: March 25, 2026
Prepared By: Hari

1. 📌 Introduction
1.1 Purpose

This document defines the functional and non-functional requirements for Version 2 of GitLens Visual, a web-based interactive Git visualization and management platform.

1.2 Scope

GitLens Visual aims to:

Simplify Git repository understanding through visualization
Enable users to manage repositories (branches, commits, PRs)
Provide AI-powered insights and analytics
Deliver a modern alternative to traditional Git interfaces
2. 🎯 Objectives
Provide real-time Git activity visualization
Enable full repository management (including PRs)
Enhance developer productivity using AI insights
Improve collaboration via interactive tools
Ensure high performance, security, and scalability
3. 👤 User Classes
User Type	Description
Beginner Developer	Needs simplified Git understanding
Intermediate Developer	Uses visualization for debugging
Advanced Developer	Uses full Git management features
Team Collaborator	Works on shared repositories
4. 🧩 System Overview
4.1 System Architecture
Frontend: React + Vite
Backend: Node.js + Express
Communication: REST APIs + WebSockets
External APIs: GitHub REST API, Webhooks
Optional AI Layer: LLM API integration
5. 🚀 Functional Requirements
5.1 Authentication & User Management
FR-1: OAuth Login
Users shall authenticate via GitHub OAuth 2.0
System shall securely store access tokens
FR-2: Session Management
Tokens shall be stored using HTTP-only cookies
Sessions shall auto-expire and refresh securely
5.2 Repository Management
FR-3: Repository Listing
Display all repositories (owned + collaborated)
Show metadata:
Name
Visibility
Last updated
FR-4: Repository Explorer (Enhanced)
Users shall:
Open repository details
View branches, contributors, languages
5.3 Commit Visualization
FR-5: Interactive Commit Graph
Display commits as nodes
Show parent-child relationships
Support:
Zoom
Pan
Center on HEAD
FR-6: Graph Filtering
Filter commits by:
Author
Date
Branch
5.4 Commit Operations (NEW)
FR-7: Commit Creation
Users shall:
Edit files
Create commits
FR-8: Commit Actions
Users shall:
Revert commits
Cherry-pick commits
Amend commits
5.5 Pull Request Management (NEW - CRITICAL)
FR-9: Create Pull Request
Select source and target branch
Add title and description
FR-10: View Pull Requests
Display:
Status (open/closed/merged)
Author
Timeline
FR-11: Review Pull Requests

Comment on PR

6. ⚙️ Non-Functional Requirements
6.1 Performance
Repo load time ≤ 3 seconds
Graph rendering ≤ 2 seconds
6.2 Scalability
Backend shall be stateless
Deployable on serverless platforms
6.3 Security
Use OAuth tokens securely
No sensitive data stored locally
Use HTTPS for all requests
6.4 Usability
Intuitive UI for beginners
Advanced controls for experts
6.5 Reliability
System uptime ≥ 99%
Graceful error handling
6.6 Maintainability
Modular code architecture
Clean API design
7. 🧪 System Constraints
Dependent on GitHub API rate limits
Requires internet connectivity
OAuth scopes must be approved by GitHub
